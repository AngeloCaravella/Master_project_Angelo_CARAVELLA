### 1. DDPG (Deep Deterministic Policy Gradient)

Deep Deterministic Policy Gradient (DDPG) is an off-policy algorithm that can operate over continuous action spaces. It concurrently learns a Q-function (the Critic) and a policy (the Actor).

The Critic network learns the action-value function (Q-value), which estimates the expected return after taking a specific action in a specific state. It is updated using the Bellman equation, similar to Q-learning.

The Actor network is a deterministic policy that directly maps states to the specific action that it believes is optimal. It is updated by using the gradient of the expected return, where the Critic's Q-value provides the signal for how the Actor's policy should change to select better actions.

To stabilize learning, DDPG uses "target networks" for both the Actor and Critic. These are copies of the main networks that are updated slowly, providing a stable target during the training process.

```mermaid

    subgraph DDPG["DDPG: Technical Flow"]
        direction LR
        subgraph CriticUpdate["Critic Update (Q-Network)"]
            direction TB
            A1["1. Sample a minibatch of transitions from the replay buffer"] --> A2;
            A2["2. Calculate a target value using the reward and the target Actor/Critic networks' evaluation of the next state"] --> A3;

        subgraph ActorUpdate["Actor Update (Policy Network)"]
            direction TB

            B3["3. Update the main Actor's weights in the direction that leads to higher Q-values (better actions)"]
        end

        subgraph TargetUpdate["Target Network Update"]
            direction TB
            C1["The target networks for both Actor and Critic are updated slowly ('soft update') to track the main networks."]
            C2["This provides a stable learning target and improves convergence."]
        end
    end
```

### 2. SAC (Soft Actor-Critic)

Soft Actor-Critic (SAC) is an off-policy actor-critic algorithm based on the maximum entropy reinforcement learning framework. This means the agent's objective is to maximize not only the expected cumulative reward but also its policy's entropy.

Entropy is a measure of randomness. By encouraging high entropy, the policy is incentivized to explore more widely and avoid converging prematurely to a suboptimal strategy. The trade-off between maximizing reward and maximizing entropy is controlled by a temperature parameter, alpha, which can be automatically tuned during training.

To improve performance and stability, SAC employs several key mechanisms: it learns a stochastic policy, uses two separate Q-functions (Critics) to mitigate positive bias in policy improvement (the "clipped double-Q" trick), and uses soft updates for its target networks.

```mermaid
graph TD
    subgraph SAC["SAC: Technical Flow"]
        direction TB
        S1["<b>Core Idea:</b> The agent learns to act successfully while also acting as randomly as possible."] --> S2;
        S2["<b>Networks:</b><br/>- One Actor (stochastic policy)<br/>- Two Critics (Q-functions)<br/>- Two Target Critics (for stability)<br/>- An adjustable temperature parameter (alpha)"] --> S3;
        S3["<b>Critic Update:</b> The two Critics are trained to estimate the action-value. The target value includes not only the future reward but also the entropy of the policy at the next state."] --> S4;
        S4["<b>Actor Update:</b> The Actor is updated to choose actions that maximize the values estimated by the Critics, plus the future entropy of its own policy."] --> S5;
        S5["<b>Temperature Update:</b> The alpha parameter is automatically adjusted to maintain a target level of policy entropy, balancing exploration and exploitation."]
    end
```

### 3. PER (Prioritized Experience Replay)

Prioritized Experience Replay (PER) is a technique that improves the learning efficiency of from past experiences in off-policy algorithms like DDPG and SAC.

Instead of sampling transitions uniformly from the replay buffer, PER samples them based on a priority. This priority is determined by the magnitude of the Temporal Difference (TD) error, which is calculated by the Critic. A high TD error indicates a "surprising" or unexpected transition where the Critic's prediction was very wrong. The agent has more to learn from these surprising transitions.

By focusing the training on these high-error transitions, the agent can learn more efficiently. To correct for the statistical bias introduced by this non-uniform sampling, PER uses Importance Sampling (IS) weights. These weights scale the magnitude of the learning update for each transition in a sampled batch, ensuring that the learning process remains unbiased in expectation.

```mermaid
graph TD
    subgraph PER["PER: Technical Flow"]
        direction TB
        P1["<b>Standard Replay:</b> Sample random transitions from memory."] --> P2;
        P2["<b>PER Method - Step 1 (Prioritization):</b><br/>When a transition is first experienced, its TD error is calculated.<br/>This error becomes its 'priority' in the replay buffer."] --> P3;
        P3["<b>PER Method - Step 2 (Sampling):</b><br/>Transitions are sampled from the buffer with a probability proportional to their priority.<br/>'Surprising' transitions are sampled more often."] --> P4;
        P4["<b>PER Method - Step 3 (Correction):</b><br/>To avoid bias, an 'Importance Sampling' weight is calculated for each sampled transition.<br/>This weight scales the learning update, down-weighting updates for high-priority transitions to ensure stability."]
    end
```
